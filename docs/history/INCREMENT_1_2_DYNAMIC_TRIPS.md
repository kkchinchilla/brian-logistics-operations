# Increment 1.2 — 動態配送趟數（Phase 1 UI 原型擴充）

## 本次調整

原本每日出勤表將各配送類別固定為「日配 2 趟、OC 3 趟、鮮二 3 趟、冷凍 4 趟、低鮮 4 趟」。現在表頭改由資料動態產生，**可以顯示第 5、6 趟以上**。每趟仍採「路線、車號」兩個並排欄位，保持原版型與橫向捲動。

### 操作

1. 透過 VS Code Live Server 開啟 `attendance-board.html?demo=1`。
2. 將示範身分切換為「主管」。
3. 點選「調整趟數」，在「冷凍」使用 `＋` 從 4 調到 5、6。表格會立即出現 `冷凍5`、`冷凍6` 及對應的車號欄。
4. 可點擊新增欄位的儲存格，輸入路線與車號，預覽異動。
5. 若該欄已經有資料，點 `－` 不會將有資料的欄位隱藏。切換日期後，各日期可有不同的趟數。
6. 切換為「司機」後，仍能看到全公司完整表格，但不能改整張表的欄位數量，也不能修改其他司機的紀錄。

### 與現有資料來源的關係

- **這是前端原型更新，不需執行新的 SQL**，不修改 `runs`、`trip_executions` 或其他既有表格。
- 接上現有 Supabase 的唯讀檢視時，**只有路線代碼明確對應欄位**（例如 `冷凍5`、`OC4`）才能自動擴充該組的欄位。其他代碼（例如 `UAT-01`）仍放到「其他路線」，不自行猜測。
- **「日配、OC、鮮二、冷凍、低鮮」是既有 Excel 的出勤欄位類別，不應擅自視為 Supabase `temperature_zone` 的完整分類。** 第二階段必須先確認「路線 → 出勤類別／顯示次序」的正式對應規則，再由實際當日各組趟次數自動產生表頭。
- 目前欄位增減、異動與結案仍只在當前頁面的記憶體中模擬，**重新整理頁面後不會保存**；主管的即時共享、日終結案及司機資料庫寫入需待後續開發。
- 每一組原型暫採最多 50 趟作為瀏覽器效能保護，**不是公司業務規則**；正式版應按資料量規劃虛擬化或分組顯示。

### 安裝

- **完整包**：解壓縮後用 VS Code 開啟 `dispatch-system-v0.5.5`；請保留原本已設定的 `js/config.js`。
- **增量修正包**：將 ZIP 解壓縮到**現有 `dispatch-system-v0.5.5` 資料夾的上一層**（與前一版路徑修正一致），確認合併覆蓋三個 UI 檔案及測試。
- 測試：`node tests/check_attendance_ui_v12.js`、`node tests/check_attendance_dynamic_v12.js`、`node tests/check_attendance_dynamic_live_v12.js`。

### 介面規格保持不變

深灰底、白色文字、黃色少量重點標示、無漸層、無頭像、無冗餘唯讀圖示。主管及司機仍以全公司每日出勤表為首頁。手機端橫向捲動與左側司機姓名固定欄維持不變。
