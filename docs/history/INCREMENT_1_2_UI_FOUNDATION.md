# Increment 1.2 · 四大 Dashboard UI 整合（第一階段）

## 安裝

將增量 ZIP 解壓縮到**包含** `dispatch-system-v0.5.5` 資料夾的上一層目錄，讓檔案合併到原本專案。

- 舊檔 `dispatcher.html`、`driver.html` 僅增加 UI 預覽入口；**原有 `attendance-board.html` 入口也保留**，原本登入、派車、回報及審核 JS 均未修改。
- 若之前的專案已有 `js/config.js`，**不要覆蓋它**。本次增量 ZIP 不包含 `js/config.js`。
- 在 VS Code 以 Live Server 開啟 `ui-attendance.html`；其餘可從上方選單切換。

## 包含的四份最終設計

1. `ui-attendance.html`：以你上傳的「每日出勤 v2」為準（沒有獎懲／薪資加給的編輯入口）；仍保留動態趟數及日終結案的模擬操作。
2. `ui-routes.html`：可自由增減配送地區／溫層與費率的 UI 示範。
3. `ui-vehicles.html`：車輛與自有車司機綁定 UI 示範，沒有「租車判定」tab。
4. `ui-monthly.html`：薪資加給、獎勵／懲處由月報管理，懲處一律輸入正數並自動扣除。

每頁都拆成獨立 HTML、CSS、JS，另外加上 `css/dashboard-shell.css` 與 `js/dashboard-shell.js` 負責共用導覽與真正螢幕寬度響應。沒有 CDN、框架或外部字體依賴。

## 本階段範圍與驗收

- 真正的瀏覽器寬度判斷，不再需要使用原型「Desktop/Mobile preview」按鈕。
- 320、375、390、768、900、1024、1366、1920 px 響應式檢視：側欄與上方導覽、表格水平捲動、固定司機欄、窄螢幕操作及編輯面板。
- 四頁互相連通，並保留舊版工作流程作回歸比對。
- 本次**不是** Supabase 正式資料寫入版：四份定稿 HTML 的編輯仍存於各自瀏覽器 localStorage，互不共享。月報試算費率/金額為示範資料，不能用於正式薪資。

## 之後的後端增量（需分步導入）

1. 地區與溫層主檔、路線定價及生效期間，不能把路線配送費直接視為司機薪資。
2. 車號／自有車司機綁定歷史與租車按實際配送趟次判定。
3. 每日出勤共用資料、原定與實際差異、RLS（司機他人唯讀）、即時更新與日終鎖定，建立防止衝突與重複計酬規則。
4. 月報取已結案出勤；薪資加給與獎懲僅月報可編輯，薪資試算確認後再做正式結薪。

不要將上述本機示範資料當作正式資料直接上傳。正式寫入前要新增 migrations、RLS 驗證與多人一致性測試。
