# Increment 1.4.1 — 每日出勤「調整趟數」補齊

依照已定稿 `Daily_Attendance_Dashboard_v2.html` 與使用者提供的操作截圖製作。

## 交付內容

- 主管在「每日出勤」搜尋列附近可看見 **調整趟數**，結案後隱藏；司機無此管理入口。
- 開啟視窗可調整每一天的五個類別：**日配、OC、鮮二、冷凍、低鮮**，初始欄數為 2／3／3／4／4。
- 每增減一趟，同步增減一組 **路線／車號** 兩個欄位。可擴至 30 趟／類別／日，不在 UI 自動刪除任何配送紀錄。
- 按「取消」只捨棄編輯；按「完成」呼叫 Supabase RPC，**一個資料庫交易**儲存五類設定。不同日期與使用者共用，刷新後可讀回。
- 用 `daily_attendance_slot_counts` 保存欄位總數，`runs.attendance_category` 及 `runs.attendance_slot_index` 明確保存各趟次在出勤表的位置。兩欄與薪資計算、路線溫層 **分離**。
- 舊資料保持原樣：沒有類別＋欄位序號的 runs 暫放「其他路線」；主管可進入既有的「修改預排趟次」選擇類別及欄號。**禁止根據溫層推測**日配／OC／鮮二等歸類。
- 同司機、同日期、同類別、同欄號不允許重複指派；已有資料的最後一趟不可被縮掉。SQL trigger 另限制已結案日期及已確認趟次的分類修改。
- 只更新每日出勤的 HTML／JS 並新增單獨的 CSS，其他三個 Dashboard 的既有頁面與樣式保持不變。
- **舊部署尚未執行 SQL 時**，新版 UI 仍能以舊版溫層表格讀取既有資料；此時不會假裝可以儲存欄位設定，並顯示安裝 SQL 的提示。

## 安裝步驟（正式環境需先備份）

1. 備份目前可用的 `dispatch-system-v0.5.5` 目錄，並確認 Supabase 資料庫可回復。
2. 在 **測試 Supabase 專案** 的 SQL Editor，確認先前 `132_01_shared_dashboard.sql` 與 `140_01_closed_day_run_guard.sql` 已安裝，再執行 `sql/141_01_attendance_column_counts.sql`。這個增量**不重建資料表、不刪除 runs、不修改歷史分類、不插入展示資料**。接著執行 `sql/141_02_verify_readonly.sql` 檢查。
3. 使用非正式營運的測試日期與測試司機／路線，先驗收下方操作；正式環境確認資料庫備份後再執行一次上述 SQL。
4. 解壓 Patch ZIP 到 `dispatch-system-v0.5.5` 的**上一層**，合併覆蓋同名檔案。保留本來的 `js/config.js`，不需要修改 Supabase URL 或金鑰。
5. 用主管帳號登入 `ui-attendance.html`，強制重新整理（macOS `⌘⇧R`），測試按「調整趟數」。

## 驗收 checklist

1. 主管有「調整趟數」，司機沒有。結案後不可調整；重新開啟後恢復。
2. 把「冷凍」4 趟調到 5 趟，應出現 `冷凍5` 和 `車號` 兩欄；按「取消」不保存，按「完成」才保存。刷新及其他帳號應讀到同樣的欄數。
3. 不同日期可設定不同欄數；切換回日期應保留當日設定。
4. 新增配送趟次時選擇出勤類別與序號，兩者**不可由溫層自動推測**。測試指定「冷凍5」後應出現在對應的司機、欄位。
5. 有資料的最後一趟，減少鍵應 disabled。若另一位主管在同時改動，資料庫也應拒絕隱藏資料的縮欄操作。
6. 同一司機同類同欄位新增兩筆，資料庫 UNIQUE 索引應拒絕。原本 DB 的司機／車輛時段重疊規則仍應有效。
7. 舊有不帶出勤欄位代碼的配送要完整顯示在「其他路線」，直到主管人工分類。**不能自動把溫層當成 Excel 出勤類別。**
8. 已確認趟次及已結案日期禁止以此操作修改既有紀錄。檢查司機帳號不可呼叫設定 RPC 成功。
9. 裝置寬 320/375/768/1366px 彈窗與表格正常、沒有整頁水平溢出。

## 測試與限制

- `node tests/check_increment_141.js`（靜態、非破壞性）及 Increment 1.4 原有測試通過。
- 隔離 Chromium 模擬後端 UI 測試，320／375／768／1366px 四個寬度通過：開窗、取消、儲存、舊列遷移分類、禁止縮減已有資料、結案鎖定、JavaScript 例外及頁面溢出。
- **尚未連接真實 Supabase 執行 migration、測試 RLS 或完成真實多使用者併發驗收。** 資料庫操作的正式可用性必須以測試 Supabase 專案驗收為準。
- 未添加計薪規則，未修改月報／租車／特殊勤務計算。
